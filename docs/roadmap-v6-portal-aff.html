05 · Release gates

Bốn lần phải dừng để chứng minh

Mỗi gate ngăn một kiểu “xong giả”: có UI nhưng chưa có authority, có attribution nhưng chưa giữ nguồn, hoặc có ledger nhưng không chứng minh payout đúng.

Gate A · Design

Ready for Task

Founder chốt open decisions; generic model, migration và LIVE target rõ.

  • `aff_plan.md` → DESIGN_ACCEPTED
  • Tier 1 mới tách AFF-01 contract
Gate B · Trust

Attribution proven

First-click, token/cookie, RPC owner/grants và RLS PASS trên DB test.

  • Forged input fail safe
  • Replay không đổi source
Gate C · Value

Source reaches ledger

Convert/placement giữ nguồn; milestone tạo đúng một beneficiary credit.

  • Race không duplicate
  • Cross-user abuse bị chặn
Gate D · GA

Safe rollout

Dark launch, shadow commission, controlled payout, monitoring và rollback.

  • Không dual-write drift
  • Cleanup có audit riêng
Pipeline

Tier 1 → 2 → 3

Mỗi slice là một contract nhỏ; không gom schema + RPC + commission.

  • HANDOFF evidence thật
  • AUDIT độc lập rồi ACCEPTED
Operations

Production safety

Additive migration, feature flags, restartable backfill và rollback.

  • Không apply/seed prod từ agent
  • Financial fix bằng reversal

Không trust clientReferrer và beneficiary đều server-derived.
