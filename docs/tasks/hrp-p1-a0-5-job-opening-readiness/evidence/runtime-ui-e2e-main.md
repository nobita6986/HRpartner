## 5. Limitations

- **APPLY_IP rate-limit bucket** is exhausted in dev memory mode (limit 2 per 600s under
  unknown-IP bucket). In production with UPSTASH_REDIS_REST_URL configured, the limit is
  10 per 600s keyed by client IP (deterministic via `clientIpFromHeaders` only when
  `VERCEL_ENV=production`; dev/preview/test → unknown + UNKNOWN_BUCKET_DIVISOR=4 → 2/600s).
- **NODE_ENV=development** is required for the in-process memory rate-limit provider fallback
  (`PORT: resolveRateLimitConfig` throws `CONFIG_MISSING` in production without Upstash
  env vars, causing 503 `RATE_LIMIT_UNAVAILABLE` for all rate-limited endpoints). This is
  fail-closed-by-design; production deployment requires Upstash Redis configured per
  `.env.example`. This is documented as expected prod posture.

  `C:\cre_hrp.txt`. Production DB access is NOT used; production migration is `NOT_RUN` (per
