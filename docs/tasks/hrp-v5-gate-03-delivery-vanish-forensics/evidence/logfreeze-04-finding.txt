METHOD, and the limit of the method
-----------------------------------
The byte cut works: every file was read as open(path,'rb').read(N) where N is the size
recorded in logfreeze-01-manifest.txt BEFORE any search ran, so nothing this extraction
caused to be logged can appear in the slices. Byte offsets are exact; timestamps are not,
which is why no timestamp parsing is used anywhere.

The cut does NOT clean what was already there. Searches run earlier in this same
conversation - before the manifest was taken - are inside the cut and are indistinguishable
from real events by keyword alone. Therefore a keyword hit in logfreeze-02-slices.txt is
NOT by itself evidence of a file operation; the line must be read, and a line of the form
`[auto-mode] new action being classified: {"Bash": ...}` is a command echo, not an event.
