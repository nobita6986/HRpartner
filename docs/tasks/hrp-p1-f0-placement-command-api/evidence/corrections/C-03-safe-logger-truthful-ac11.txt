C-03 — Structured safe logging & truthful AC-11
===================================================

Round: 2 (v1.2)

Change:
-------
File: `src/domains/talent/placement.route-helpers.ts`

Replaced `console.*` with canonical `src/shared/observability/logger.ts`
+ `src/shared/observability/correlation-id.ts`. Helper now emits:

  Success:  info    "placement.command.success"
            route, method, status, actorRole, resourceType, outcome,
            errorCode (omitted), detail: { command, placementId, replayed }

  Auth fail: warn   "placement.command.auth_failed"
            route, method, actorRole=undefined, resourceType, outcome=auth_failed,
            errorCode: <AuthSessionError.code>, detail: { command }

  Auth 500: error  "placement.command.auth_internal_error"
            route, method, actorRole=undefined, resourceType, outcome=auth_internal_error,
            errorCode: 'INTERNAL', detail: { command }

  Canonical error: warn "placement.command.canonical_error"
            route, method, status, actorRole, resourceType, outcome, errorCode,
            detail: { command, placementId: '[REDACTED]' (sensitive UUID), replayed }

  Unexpected: error "placement.command.unexpected_error"
            route, method, status, actorRole, resourceType, outcome,
            errorCode: 'INTERNAL', detail: { command }

All metadata respects SafeMeta allow-list. Detail object is the designated
overflow container (per logger.ts §PLN-03).

Forbidden fields — explicitly NOT logged:
  raw `actorId`
  request body
  evidence values
  `acknowledgementRef`
  `failureReason` (may contain PII)
  tokens
  `Idempotency-Key`
  any PII

AC-11 / RQ-11 v1.2 truthful rewrite:
  - Dropped fabricated `managementMode/fromStatus/toStatus` (service result
    does not provide them; F0 must NOT fabricate)
  - Field set reduced to what the implementation actually supports
