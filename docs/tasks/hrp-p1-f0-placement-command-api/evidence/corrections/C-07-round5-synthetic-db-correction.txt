ROOT CAUSE (corrected understanding):

  The SECT B implementation contained two latent defects:

  Defect 1 (line 604 query):
    Code path: SELECT id FROM labor_profiles
               WHERE normalized_phone = $1 AND slot_id = $2

    `slot_id` lives on `candidate_submissions`, NOT on
    `labor_profiles`. The query therefore fails at SQL parse with
    `column "slot_id" does not exist`. The T1B local sandbox does
    NOT have a LIVE synthetic DB, so this defect was not exercised
    during in-unit verification; it only surfaced on T0's staging
    writer/admin pair.

    Correct resolution: collect labor_profile_id and
    placement_case_id from candidate_submissions BEFORE delete:

      SELECT id, labor_profile_id, placement_case_id
      FROM candidate_submissions
      WHERE id = ANY($1::text[])

    then derive `lpIds` and `pcIds` from those rows (no need to
    re-query labor_profiles for slot_id).

  Defect 2 (FK-safe reverse order incomplete):
    The previous teardown deletes `labor_profiles` BEFORE clearing
    `candidate_submissions.labor_profile_id`. With RestrictOnDelete
    semantics on the candidate_submissions.labor_profile_id FK, that
    sequence cannot succeed. The cleanup also deletes
    `application_status_history` BEFORE deleting
    `candidate_submissions`, which violates the
    application_status_history.submission_id -> candidate_submissions.id
    FK direction.

    Correct FK-safe reverse order:
      1. Clear candidate_submissions.labor_profile_id + .placement_case_id
         (NULL them) for any rows that point at the lpIds / pcIds.
      2. DELETE FROM application_status_history WHERE submission_id = ANY($1).
      3. DELETE FROM candidate_submissions WHERE id = ANY($1).
      4. DELETE FROM placement_cases WHERE id = ANY($2).
      5. DELETE FROM labor_profiles WHERE id = ANY($3).
      6. (job fixture hierarchy, unchanged):
         DELETE FROM job_postings WHERE id = $post.
         UPDATE staffing_order_slots SET job_opening_id = NULL.
         DELETE FROM job_openings WHERE id = $open.
         DELETE FROM staffing_order_slots WHERE id = $slot.
         DELETE FROM staffing_orders WHERE id = $order.
         DELETE FROM outsourcing_projects WHERE id = $proj.
         DELETE FROM client_companies WHERE id = $cc.
