C-04 — Fail-closed delegation detector
=========================================

Round: 2 (v1.2)

Change:
-------
File: `src/domains/applications/marketplace-inventory.static.test.ts`

Removed hard-coded `ADMIN_GUARDED_VIA_HELPER` allowlist (which v1.1 used
to enumerate specific route file names). Replaced with a SINGLE canonical
classifier function used by BOTH the production route inventory AND the
negative fixture:

  classifyMutatingPlacementRoute(routeSource) -> { guarded: true } | { guarded: false, reason }
    Path A — AUTH_MARKER present in source         -> guarded: true
    Path B — delegates to handler sibling with AUTH_MARKER -> guarded: true
    Path C — uses placement.route-helpers delegation:
      (1) MUST import from `placement.route-helpers` (named or default)
      (2) MUST have actual `runPlacementCommand(` CALL EXPRESSION
      (3) helper MUST export `runPlacementCommand` AND contain
          ACTUAL `getAuthContext(` AND `withDbContext(` CALL EXPRESSIONS
    ANY condition missing -> guarded: false, with specific reason:
      - 'no_helper_import'
      - 'no_helper_call'
      - 'helper_missing_security_markers'

Round 2 + F-02 SUBSTANTIVE PROOF:
- Marker checks REQUIRE call expressions (`getAuthContext(`), not bare
  identifier presence. A comment like `// uses getAuthContext` no longer
  satisfies the check.
- The negative fixture
  `tests/security/admin-route-fail-closed.negative-fixture.ts` is run
  through the SAME `classifyMutatingPlacementRoute` function used by
  the production route inventory — so "proves detector catches" is
  now a measurable, reproducible assertion.

Negative fixture (new file): `tests/security/admin-route-fail-closed.negative-fixture.ts`
  - declares `export async function POST`
  - does NOT import placement.route-helpers
  - does NOT call `runPlacementCommand`
  - does NOT contain `getAuthContext(` or `withDbContext(` call expressions
  - classifier returns `{ guarded: false, reason: 'no_helper_import' }`
