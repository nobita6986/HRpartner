## 1. Outcome

### 1.1 User-visible outcome

- Ứng viên ẩn danh (N1) truy cập `/viec-lam/[slug]` (A1 đã cutover) → nhấn "Ứng tuyển" → điền form → `POST /api/public/jobs/[slug]/applications`:
  - Rate-limit IP + phone giữ nguyên (DUAL bucket) — reuse helper read-only.
  - Body shape gate hand-crafted (đồng nhất A1 §4.2); CV non-null vẫn 422 `CV_UPLOAD_DISABLED`.
  - Node chỉ validate/normalize/hash/mint tracking code, gọi RPC, map public response — KHÔNG gọi `createOrMatchLaborProfile`/`openPlacementCase`/tác vụ write khác.
  - SECURITY DEFINER RPC `hrp_public_apply_submission` (đã được A1 thay body để validate `PUBLISHED JobPosting + OPEN JobOpening + bound available slot`; P1-B thay body tiếp để mirror score/case/submit chain) là **mutation authority duy nhất** cho:
    - Revalidate `JobPosting.status='PUBLISHED'` + `JobOpening.status='OPEN'` + slot bound + slot ngoài linked opening reject.
    - Gọi lại DB helper canonical `hrp_score_labor_profile(...)` thay vì copy/reimplement thuật toán trong function body.
    - EXACT_MATCH → reuse `LaborProfile`; NEW_PROFILE → INSERT `labor_profiles`; POSSIBLE_MATCH → fail closed, không tạo partial application/profile/case.
    - Open hoặc reuse `PlacementCase` qua partial unique index bằng PL/pgSQL exception-block subtransaction; KHÔNG phát hành câu lệnh `SAVEPOINT` tường minh trong function.
    - INSERT `CandidateSubmission` với `labor_profile_id` + `placement_case_id` gắn; INSERT initial `application_status_history` (NULL→'NEW', reason='PUBLIC_APPLY'). Vendor_id=ctv_id=NULL cho anon (DEC-13).
    - Toàn bộ chain rollback atomic nếu bất kỳ bước nào fail.
    - DB-level idempotency replay giữ nguyên invariant hiện hành: same key + same payload → stored `tracking_code`/`status`; same key + different payload → `P0010`/409; concurrent same-key → exactly one canonical mutation. **KHÔNG** wrap service với `withIdempotency`/`idempotency_keys` trong slice này.
  - Public response chỉ exact function signature result: 201 với `{ trackingCode, status }`. KHÔNG leak `candidateSubmissionId`, `laborProfileId`, `placementCaseId`, `verdict`, candidate list, signals. Integration test đọc các internal ID trực tiếp từ synthetic DB nhưng KHÔNG có chúng trong HTTP/RPC result.
  - POSSIBLE_MATCH → `409 POSSIBLE_MATCH_NOT_RESOLVED` chung, không candidates, không internal IDs, không PII, không row-existence detail.
- Tracking read `GET /api/public/applications/[trackingCode]` tiếp tục phục vụ DTO với `fullName` + masked `phoneMasked`/`cccdMasked`, không đổi schema. P1-B chỉ verify `CandidateSubmission` row mới tương thích field shape (id, public_tracking_code, status, created_at, full_name; left join staffing_order_slots + outsourcing_projects).
- Slug-bound apply KHÔNG đọc/bind `hrp_aff` cookie. Referral attribution cho slug-bound apply là task additive riêng.
- Khi n8n unavailable: apply vẫn thành công (HRP-owned write chain; n8n chỉ là post-commit notification tách biệt — task riêng ngoài P1-B).
